# Updated (repo: AI_Updated)

Static site (GitHub Pages, branch `master`, root) with one tab per **domain** (`config/domains.json`): AI (≤2 news
+ ≤5 papers), Business (≤5 news + ≤1 research), Science (≤3 news + ≤3 papers), Biology (≤3 news + ≤3 papers),
Tech beyond AI (≤4 news + ≤1 research), each item 250–350 words, Mon–Sat.
AI also has Trends (monthly summary on the 1st, field model, stock-style pages, Week in review); Jobs is a
cross-domain board.
Live: https://guaaaaa.github.io/AI_Updated/ (`#/ai`, `#/business`, `#/science`, `#/biology`, `#/tech`, `#/jobs`)

- **Daily AI run (Mon–Sat) → follow `RUNBOOK.md` exactly.** Saturday is "best of the week"; Sundays have no digest.
- **Other daily runs → `RUNBOOK_<DOMAIN>.md`** (`RUNBOOK_BUSINESS.md`, `_SCIENCE`, `_BIOLOGY`, `_TECH`). Every command
  takes `--domain <id>`; without it scripts work on AI. Tech skips stories that are mainly about AI (they belong to the
  AI tab); Biology covers all life sciences incl. medicine (no health policy) and never gives medical advice; Science
  has no biology (shared sources are split by `common.life_science`). One story or paper per tab (`other_tabs`).
  Every tab has an automatic Week in review (`#/<tab>/week/<id>`; AI's sits in Trends). `#/` is the Today page (every
  tab's latest highlights). Each tab's `index.json` is small; its items are in `<tab data>/items/YYYY-MM.json` (loaded
  only for browse/search); RSS feeds in `data/feeds/` (all generated by `build_index.py`).
- Colours: `assets/themes.css` is generated by `pipeline/make_themes.py` (one scheme: light "Spring garden", dark "Night
  sky"; OKLCH-uniform pastels, text inks >= 4.5:1, chart colours validated). Edit the scheme there, never the CSS.
- `.claude/settings.json` keeps the scheduled runs lean: it turns off Claude Code features and tools the runs never
  use (about 18k fewer tokens in every request) and keeps large command output inline. Keep `Bash`, `Read`, `Write`,
  `Edit`, `WebSearch` and `ToolSearch` available.
- **Monthly scheduled run (1st) → follow `RUNBOOK_SUMMARY.md` exactly** (AI). Every trend claim rests on
  field-level evidence, never on our own picks. There is no weekly summary: `pipeline/week_review.py` builds the
  Week in review.
- Domains: `pipeline/common.py` reads `--domain` (or `AIU_DOMAIN`, exported to child scripts). AI keeps the original
  paths (`data/days/`, `config/*.json`, `work/`); another domain uses `data/<id>/`, `config/domains/<id>/` (its
  `sources.json`, `taxonomy.json`) and `work/<id>/`. `build_index.py` always rebuilds every domain's index,
  `data/domains.json`, AI trends and jobs. News-led domains get papers from `pipeline/fetch_research.py`.
- Layout: `index.html` + `assets/` (front end, no build step; `trends.js` = dashboard) ·
  `data/days/YYYY-MM-DD.json` (digests) · `data/summaries/monthly/<id>.json` (trend summaries) · `data/weeks/`
  (AI's Week in review; other tabs: `data/<id>/weeks/`) · `data/index.json` + `data/trends.json` (generated by `pipeline/build_index.py`) ·
  `data/state/` (alphaXiv Hot snapshots, per-day shortlist/headline snapshots in `daily/`, monthly field-wide
  aggregates in `field/` from `pipeline/field_stats.py`, per-announcement-day series in `field_daily/` from
  `pipeline/field_daily.py`, updated automatically by `fetch_papers.py`) · `data/daily.json` + `data/fields/` +
  `data/directions/` (generated page data for the stock-style direction and field pages) · `data/state/jobs/` (job
  board: open-postings registry, daily role metrics, Hacker News / Indeed / AI-exposure history, written by
  `fetch_jobs.py` from `prepare.py` and `jobs_history.py`) · `data/jobs.json` + `data/jobs/` (generated by
  `pipeline/build_jobs.py`) · `config/` (taxonomy, sources, notable authors/labs,
  research `directions.json`, `industry.json`, job roles `jobs.json`, `employers.json`, site) · `pipeline/` (Python 3 stdlib + bs4) · `work/` (git-ignored
  scratch and caches, incl. raw monthly field data in `work/field/`).
- Time zone: America/New_York. Windows: papers 72h (Saturday 7d) by arXiv announcement time; news 72h.
- alphaXiv is used only through its free `get_hot_feed` MCP tool (`pipeline/alphaxiv.py`); the API key is
  injected by the cloud environment's network secret for api.alphaxiv.org — never write keys to the repo.
- Papers are read from arXiv (HTML, PDF fallback), never via alphaXiv's quota-consuming tools.
- Validate before publishing: `python3 pipeline/validate.py [--domain X]` (digests), `python3 pipeline/validate_summary.py`
  (summaries). Never hand-edit generated files (`data/index.json`, `data/<id>/index.json`, `data/domains.json`,
  `data/trends.json`, `data/jobs.json` ...).
